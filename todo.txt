── TRAITEMENT DES DONNÉES (rof-signup.js) ✅ ────────────────────────────────────

5. Nettoyage et reformatage des champs via expressions régulières :
   - Nom / Prénom :
     - Noms (Nom, Nom_Mère, Nom_Père) : tout en majuscules (.toUpperCase()).
       Ex : dupont martin => DUPONT MARTIN
     - Prénoms (Prénom, Prénom_Mère, Prénom_Père) : première lettre de chaque partie
       en majuscule, reste en minuscule. Les parties sont séparées par un espace ou un tiret.
       Ex : jean jacques  => Jean Jacques
            jean-jacques  => Jean-Jacques
            MARIE         => Marie
   - Numéros de téléphone : normalisation du format
     (ex: 0612345678 ou +336 12 34 56 78 ou 06.12.34.56.78 → 06 12 34 56 78 )
   - Date de naissance : vérifier et normaliser le format DD/MM/YYYY
   - Email : mise en minuscules, suppression des espaces
   - Ne pas produire de json avec une liste vide.

── EXTENSION CHROME 🚧 ───────────────────────────────────────────────────────

6. Soumission automatique du formulaire depuis l'extension :
   - Proposer un bouton pour traiter tout le lot.
     les items seront alors traités un par un. L'extension remplit et soumet le formulaire,
     puis attends le resultat du call API. Si le code correspond à un succès, l'item est enlevé
     de la liste, et on passe au suivant.
     Si le code correspond à un echec, l'item est toujours present dans la liste. On y affiche alors
     un bouton pour retenter la soumission.
   - Proposer également pour chaque item un bouton permettant de traiter individuellement l'item.
   - Proposer un bouton pour suspendre le traitement.
     Il faut alors pouvoir renvoyer à l'application node l'ensemble des items
     qui n'ont pas été traités pour mettre à jour le fichier json plutôt que le supprimer.

7. Gestion de la réponse du site après soumission :
   - Succès (HTTP 201) : marquer l'item comme traité automatiquement,
     afficher une confirmation dans le popup.
   - Erreur serveur (HTTP 401, 403, 500) : afficher le message d'erreur,
     proposer de réessayer.
   - Erreur réseau : signaler que le site est inaccessible.

8. Synchronisation du fichier JSON lors du traitement item par item :
   - Problème : quand l'utilisateur traite les items manuellement (un par un),
     les items supprimés de l'UI ne sont pas retirés du fichier JSON sur le serveur.
     Le fichier reste intact jusqu'à ce que tous les items soient traités (DELETE).
   - Solution : ajouter un bouton "Sauvegarder et quitter" (ou équivalent) dans le header,
     visible dès qu'au moins un item a été traité avec succès.
     Ce bouton envoie un PATCH au serveur avec les records restants,
     permettant de reprendre le traitement plus tard sans reperdre la progression.
   - À voir : si la soumission item par item synchronise déjà le json, y'a peut-être pas besoin de
     se prendre la tête pour rien ?
     Peut-être que pour chaque item créé avec succès ( réponse http 200 ou 201 ) on peut déjà mettre à jour le json ?
